## 已确认并修复

### 执行结束后 setAutoCommit 空指针

`BorrowedConnection.close()` 原先先调用 `HikariDataSource.evictConnection()`，随后在 finally 中调用同一个 Hikari 代理的 `close()`。淘汰已经清空 `PoolEntry.connection`，再次关闭代理会按 dirty bits 恢复自动提交状态，从而触发空指针。

使用项目实际依赖的 HikariCP 6.3.3 和本地 H2，分别在提交、回滚后淘汰连接，修复前均复现与反馈一致的异常：

```text
Cannot invoke "java.sql.Connection.setAutoCommit(boolean)" because "connection" is null
PoolBase.resetConnectionState → PoolEntry.resetConnectionState → ProxyConnection.close → BorrowedConnection.invoke
```

修复后，归还和淘汰为互斥路径；淘汰由原连接池负责关闭物理连接，不再对已淘汰代理执行状态复原，也不先归还可能带有会话状态的连接。包装连接保持关闭状态，重复 close 不重复清理。真实单槽连接池测试确认新借用获得新物理会话，提交/回滚结果未改变。

后台 SCRIPT 和 BATCH 任务在所有 SQL、最终提交/回滚及进度持久化完成后，关闭 Statement/连接失败只记录收尾警告，保留 SUCCESS / COMPLETED 及事务结果。执行失败或取消仍保留主错误，附带全部直接 suppressed 收尾异常。服务日志包含 taskId、connectionId 和完整异常堆栈；SCRIPT 失败日志另含执行计数和事务结果。没有历史任务状态重写或自动重跑。

### OceanBase Oracle 执行计划语法

`OceanBaseOracleDialect` 原先继承 Oracle 的 `EXPLAIN PLAN SET STATEMENT_ID ... FOR` 和 `DBMS_XPLAN.DISPLAY` 实现，与反馈中报错片段一致。现使用 OceanBase 的 `EXPLAIN <SQL>`，直接读取计划结果，不访问或清理 Oracle PLAN_TABLE；保留超时、行数和结果大小限制。

语法依据：[OceanBase V4.2.5 官方 SQL 执行计划文档](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000001500483)。原生 Oracle 的实现未修改。

## 尚不能归因的现场现象

- 网络断流、连接被拒绝及 total=0 时补建失败，需要现场数据库、代理、网络及服务端日志确认；现有附件不足以认定为驱动或连接池自身缺陷。
- 池满时的等待超时属于资源限制，现有本地池耗尽/释放后恢复测试继续保留。
- 执行计数为 0 不证明数据库未执行。断连或提交回执丢失继续保留 UNKNOWN，禁止自动重跑；真实 SQL 错误、租户内存错误及取消不转成成功。
